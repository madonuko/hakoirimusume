# Getting Started with RPM Packaging

Welcome to the world of RPM packaging! This guide will walk you through the fundamentals of creating RPM packages.

## What is an RPM Package?

An RPM package is a compressed archive containing files to be installed on a system, along with metadata about the package. RPM packages end with `.rpm` extension and can be installed, upgraded, or removed using the `rpm` or `dnf` package managers.

## Anatomy of a Spec File

```bash
Name:           my-package
Version:        1.0.0
Release:        1%{?dist}
Summary:        A brief description of my package

License:        MIT
URL:            https://example.com/my-package
Source0:        %{url}/my-package-%{version}.tar.gz

BuildRequires:  gcc
BuildRequires:  make

%description
A longer description of what my package does.

%prep
%autosetup

%build
%configure
%make_build

%install
%make_install

%files
%license LICENSE
%doc README.md
%{_bindir}/my-program
```

## Key Sections

### Preamble

The preamble contains package metadata like name, version, license, and dependencies. All fields before the first section directive (like `%description`) are part of the preamble.

<CardGrid>
	<Card title="Name" icon="pencil">

	<Card title="Version" icon="pencil">

### %prep Section

Prepares the build environment by extracting sources and applying patches.

### %build Section

Compiles the source code using the appropriate build system.

### %install Section

Installs files to the buildroot directory, creating the package layout.

### %files Section

Lists all files that should be included in the package.

## Setting Up Your Build Environment

```bash
# Install rpmdevtools
dnf install rpmdevtools rpm-build

# Create the rpmbuild directory structure
rpmdev-setuptree

# Verify the structure
ls ~/rpmbuild/
BUILD  BUILDROOT  RPMS  SOURCES  SPECS  SRPMS
```

<Callout type="info">
  The `rpmdev-setuptool` command creates the standard RPM build directory structure in your home directory.
</Callout>
